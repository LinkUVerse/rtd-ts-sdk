# 06 · 上线顺序与验收演练

> **高优先级上线门槛**：所有测试网/未来正式网必需中间件必须自建开源，包含 MinIO、Apache HBase/HDFS/ZooKeeper、PostgreSQL、RocksDB，以及密钥、入口、备份、监控和镜像仓库。Google Cloud Bigtable/GCS、AWS S3、Azure Blob 和其它闭源云服务不得成为运行依赖。旧上游云命令不能直接照搬；先完成 [03 的 HBase 生产适配验收](./03-远程检查点归档存储与Ledger-gRPC.md)与[全栈开源验收](../../../rtd-archive-service/OPEN_SOURCE_POLICY.md)。

本章是**待执行的生产实施计划**。当前已有独立 dev 链 0–100 的开发验收证据，见[工作记录](../workLog/2026-09-24-归档统一服务建设.md)；以下生产步骤尚未通过，不能把 dev 结果记作生产通过。每一关的证据应包含：目标 RTD 链 ID、构建提交和镜像摘要、配置版本、实际命令、时间、端点响应、逐管线水位、样本输入/输出、故障演练日志和负责人签认。参照官方[通用索引器部署](https://docs.sui.io/operators/data-management/indexer-stack-setup)、[远程 checkpoint 桶](https://docs.sui.io/operators/data-management/remote-store-setup)、[归档服务](https://docs.sui.io/operators/data-management/archival-stack-setup)；本地对应 [02](./02-通用索引GraphQL与Consistent-Store.md)、[03](./03-远程检查点归档存储与Ledger-gRPC.md)。

## 3. 逐功能验收矩阵

每项至少准备一条 genesis 附近、一条跨 epoch、一条接近 Full Node 保留边界、一条链头附近的 RTD **真实已认证样本**；对不存在键另备一个明确未上链的值。样本 ID/digest、期望结果及链 ID归档保存。

| 需求/风险            | 必须执行的检查                                                                                                                                                                                                                                                               | 失败时阻断什么                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| 同链隔离             | 在**空库首次写入前**由外部准入 gate 比对预先钉住的目标创世 digest，异链源必须被拒；在**已有库**再注入异链 checkpoint，验证框架的 chain ID 绑定拒绝写入，查询也不混链。标准空库首次写入可能绑定错误链，不能把框架 CAS 当成空库准入。                                          | 所有跨层结果发布。              |
| 原始数据连续与真实性 | 检查 0..H 无洞、序号/摘要链、认证及内容；模拟缺文件、同序号冲突文件、损坏 zstd/Protobuf。                                                                                                                                                                                    | 后续水位推进与 Full Node 修剪。 |
| 历史点查             | 对同一 transaction digest、checkpoint 序号/摘要、object ID+多个版本，分别用尚保留的 Full Node 与 `rtd-kv-rpc` 比对；测试批量、read mask、旧/新边界。                                                                                                                         | 历史详情及 GraphQL 对外流量。   |
| Ledger List          | 若产品使用 `ListTransactions`/`ListEvents`/`ListCheckpoints`，启用相应参数并让三个依赖管线从 0 回填，验证协议允许的过滤、分页、watermark、扫描预算和超时；若以此替代某项全历史 PG 筛选，还须实测钱包/BFF 实际改走 Ledger List 且结果对账；否则确认接口明确 `UNIMPLEMENTED`。 | 声称支持的列表能力。            |
| 过滤索引             | 交易按地址/受影响对象/函数，事件按类型/模块，跨 checkpoint 分页与对象版本列表；用全量样本回放核对数量和详情。                                                                                                                                                                | 相关 Wallet/Mobile 历史页面。   |
| 当前状态             | 同一 checkpoint 的余额、持有对象与 Full Node 一致；Consistent Store 停滞时不显示旧值为“当前”。                                                                                                                                                                               | 余额/资产页面。                 |
| 交易路径             | 本地签名后的原交易字节提交，模拟、等待效果、用原 digest 重查；节点超时或结果未知不得重签再播。                                                                                                                                                                               | 交易迁移和 JSON-RPC 停用。      |
| 负结果与故障         | 对真不存在键、Full Node 已修剪但归档存在、归档故障、PG 落后四种情况验返回语义；不能都变成 `null`/空列表。                                                                                                                                                                    | 业务支付、订单、审计读路径。    |
| 数据库与区域故障     | 杀单个 GraphQL/归档进程、停止一个 Full Node、切 PG、断一地域 HBase/HDFS；在副本健康/水位符合条件后切流量。                                                                                                                                                                   | 高可用承诺。                    |
| 恢复                 | 从隔离副本恢复原始桶、HBase 的错时单表快照、PG PITR、Consistent Store 快照/0 起回放；HBase 快照恢复不当作跨表原子快照，未逐表补齐/重建前不切流，对相同样本比对结果与水位。                                                                                                   | 灾备与修剪范围扩大。            |
| 负载与容量           | 以 RTD 预期高峰做回填+在线并发压测，记录 p95/p99、每条管线 lag、MinIO/PG/HBase 成本和限流触发；预留增长余量。                                                                                                                                                                | 正式容量签认。                  |

官方归档 `GetServiceInfo` 报的是所需管线的**最低上界**；本地实现把最低可用下界暂时固定为 0，因此不等于“从 0 的真实数据都已验证”。详见[水位与健康的限制](./04-高可用完整性与一致性控制.md#1-不可妥协的数据不变量)。此外 `rtd-kv-rpc` 的 HTTP `/health` 只返回 `OK`，[实现](../../../temp/rtd/crates/rtd-kv-rpc/src/main.rs#L170-L172)，需真实 `Get*` 探测代替独立就绪证明。

## 4. 故障演练脚本的预期行为

1. **Full Node 断源时间短于保留窗口**：新 checkpoint 摄取停滞应告警；切到同链备用 Full Node 后按原 watermark 续跑，重复 checkpoint 不产生内容冲突。GraphQL 历史已覆盖区间仍能服务，但不宣称产生新链头。
2. **断源时间长于保留窗口**：从原始桶补齐落下的序号，检查每条 PG/HBase/Consistent Store pipeline 追平，再切回 Full Node gRPC。不能通过改变 `--first-checkpoint` 跳过历史。[官方恢复说明](https://docs.sui.io/operators/data-management/indexer-stack-setup)。
3. **某一 pipeline 停滞**：停止发布依赖该管线的查询范围，按下载、转换、提交三段定位；解决后从已提交水位重放并逐表抽样。不要直接删 watermark 或认为其他管线追平即整体追平。
4. **归档只读服务或 HBase/HDFS 故障**：切到已独立回填和验收的同链地域；只有 `/health=200` 的备用实例不能切流量。没有合格备用时显式不可用，不能返回空详情或回退至已修剪节点。
5. **错误来源/损坏对象/异链**：立即冻结原始已验证水位和相应下游，保留故障对象、校验日志、构建摘要；从独立可信副本恢复并重验。不能覆盖旧对象掩盖差异。
6. **区域级恢复**：在隔离环境用备份和同链原始桶重新构建完整数据面，记录恢复到可提供旧点查、筛选、当前状态与执行各自需要的时间；这些时间决定实际 RTO，不以 pod 数量推断 HA。

## 5. 上线签认清单

- [ ] 同源构建和链 ID 矩阵已存证；所有 RTD 占位端点已换成真实的内网/对外端点，凭据经秘密管理系统交付。
- [ ] 原始桶从 checkpoint 0 连续、认证并可恢复；事实文件的同 key 冲突拒绝、已验证版本钉住及跨故障域副本已验证；Object Lock 单独启用不算通过。
- [ ] HBase 14 表/14 管线与 `rtd-kv-rpc` 的旧点查、批量和需要的 List 功能已验收。
- [ ] PG 管线/保留期与产品承诺一致；Consistent Store 已追平；GraphQL 四后端和限额都已验收。
- [ ] Full Node 修剪下界与原始已验证水位之间保有测量过的恢复余量，监控和自动阻断有效。
- [ ] 同链与异链、旧与新、存在与不存在、故障与落后的回归用例通过。
- [ ] PG PITR、HBase 14 表错时快照与 HDFS 备份、原始桶、Consistent Store 与区域故障的**实际**恢复记录存在，RPO/RTO 符合批准目标。
- [ ] Wallet、Mobile 和业务后端真实用户路径通过；JSON-RPC 调用量经观测为零，停用演练和回滚计划通过。

以上方框默认均是**未完成状态**。只有对应现场证据生成后才能勾选；本报告的源码审阅与官方文档引用不代替构建、部署或网络验收。
